# oneweek — цель продукта

Этот документ — источник правды о том, **зачем существует oneweek и каким он должен оставаться**. Если задача, код или чужое предложение противоречат этому документу, прав документ; если сам документ устарел, его нужно обновить отдельной правкой, а не обходить молча.

Технические детали (запуск, миграции, деплой) — в [README.md](README.md). Здесь — только смысл и правила принятия решений.

---

## 1. Суть в одной фразе

> **One week on a screen — everything important in view.**
> Одна неделя на экране — и всё важное перед глазами.

oneweek — планер ровно на ту неделю, в которой человек живёт сейчас. Без шума дальних сроков, бесконечных списков и проектного менеджмента. Слоган с about-страницы: *«планер для мира, который не стоит на месте»*.

## 2. Для кого

Для одного человека, который планирует свою неделю: работа, личные дела, учёба. Не для команд. Человек открывает oneweek, видит неделю целиком, раскладывает дела по дням и закрывает их.

## 3. Принципы (в порядке приоритета)

1. **Горизонт — одна неделя.** Экран всегда показывает одну неделю: семь дней, колонку «next week» и общий список задач. Прошлые недели доступны как история, будущее дальше следующей недели — сознательно вне фокуса.
2. **Всё видно сразу.** Неделя помещается на один экран без вложенных страниц, модалок и скрытых разделов. Новая функция, которая требует отдельного экрана или прячет задачи, противоречит продукту.
3. **Минимум трения.** Задача — это строка текста. Enter создаёт следующую, Tab делает подзадачу, чекбокс закрывает. Никаких обязательных полей, форм, приоритетов и статусов.
4. **Смысл вместо метаданных.** Вместо полей «время», «приоритет», «метка» используются лёгкие сигналы прямо в тексте и цвете: `14:30` в тексте задачи — это время, цвет строки — это важность.
5. **Спокойный, личный интерфейс.** Пастельные цвета, свои темы и шрифты, мягкие анимации (с учётом `prefers-reduced-motion`). Никаких бейджей, счётчиков, уведомлений и геймификации.
6. **Задачи не теряются.** Офлайн-кэш, синхронизация между устройствами, undo для удаления, копирование (а не перенос) незакрытых задач прошлой недели, чтобы история сохранялась.
7. **Бесплатно, и точка.** Рекламы не будет никогда. Все текущие и будущие функции бесплатны для всех. Email нужен только для входа и хранения задач — никаких рассылок.

## 4. Модель продукта

| Понятие | Что это | Где в коде / данных |
|---|---|---|
| **Неделя** | Понедельник–воскресенье. Навигация стрелками, «Now» возвращает на текущую. В сайдбаре — следующая неделя и 12 прошлых. | `getWeekMondayStart`, `window.__weekOffset`, `PAST_WEEKS_COUNT` |
| **День** | Колонка с задачами, привязанными к конкретной дате. Сегодняшний день подсвечен. | `tasks.type = 'daily'`, `date`, `day_name` |
| **Next week** | Восьмая колонка: дела, которые точно на следующую неделю, но без конкретного дня. | `day_name = 'Next week'`, `date` = понедельник следующей недели |
| **Tasks (общий список)** | Задачи недели без конкретного дня; их перетаскивают в день, когда придёт время. | `tasks.type = 'general'`, `date` = понедельник недели |
| **This week’s main thing** | Одна главная задача недели в общем списке. Строго не больше одной на неделю и workspace. | `tasks.is_main`, уникальный индекс в `db/2026-08-19-task-is-main.sql` |
| **Подзадача** | Один уровень вложенности (Tab / кнопка). Родителя можно свернуть. | `tasks.is_subtask`; свёрнутость — в `localStorage` |
| **Задача по времени** | Если в тексте есть `hh:mm`, время переносится в начало, а задачи дня сортируются по времени. | `parseTimeMinutes`, `moveTimeToStart` |
| **Цвет задачи** | Одна из 9 пастельных подсветок, чтобы важное бросалось в глаза. | `TASK_COLOR_PALETTE` |
| **Move remaining tasks** | На текущей неделе: копирует незакрытые задачи общего списка прошлой недели. Копия, не перенос — прошлая неделя остаётся историческим срезом. | `setupMoveRemaining` в `js/task-panel.js` |
| **Workspace** | Отдельная доска для другой сферы жизни (вкладки в шапке). Дефолтный `main` удалить нельзя. | `workspaces`, `is_default`, `js/workspaces.js` |
| **Тема** | Цвет текста, фона и шрифт. Выбранная тема и свои темы синхронизируются через аккаунт (новее — побеждает). «Match device» (тема по умолчанию) следует системной теме: Native light днём, Native dark ночью. | `js/theme-init.js`, `js/theme-sync.js`, `user_settings` |

Правила списка, на которые опирается UX: невыполненные задачи всегда выше выполненных; порядок задаётся перетаскиванием и синхронизируется (`tasks.position`); подзадачи двигаются вместе с родителем.

## 5. Что уже решено

- **Вход обязателен.** Без аккаунта доска не показывается — открывается модалка входа/регистрации (email + пароль через Supabase). Отдельного гостевого режима с локальными задачами нет.
- **Данные пользователя защищены RLS.** Anon-ключ публичный; вся изоляция держится на политиках `auth.uid() = user_id`.
- **Офлайн — это норма, а не ошибка.** Задачи кэшируются локально, при потере сети показывается спокойный баннер, правки досылаются при восстановлении.
- **Платформа — статический PWA.** Ванильные HTML/CSS/JS без сборки и фреймворков, Supabase как бэкенд, Vercel как хостинг. Устанавливается на телефон и десктоп.
- **Мобильная версия — полноценная**, а не урезанная: всё, что есть на десктопе, должно работать на тач-экране.
- **Язык интерфейса — английский, строчными буквами** (`monday`, `this week`, `next week`). About-страница и баннер офлайна есть на en/ru.
- **Отзывы не модерируются**: плохие не удаляются, хорошие не выдумываются.

## 6. Чем oneweek не является

Это следствия принципов выше. Предложения из этого списка по умолчанию отклоняются, если владелец явно не решил иначе.

- Не таск-менеджер для проектов: нет проектов, дедлайнов через месяцы, статусов, приоритетов, исполнителей.
- Не календарь: нет событий с длительностью, повторяющихся встреч, почасовой сетки.
- Не командный инструмент: нет общих досок, комментариев, упоминаний.
- Не система напоминаний: нет push-уведомлений и email-напоминаний.
- Не продукт с монетизацией: нет платных тарифов, рекламы, трекинга ради маркетинга.
- Не «бесконечный бэклог»: горизонт — эта неделя и следующая.

## 7. Как агенту принимать решения

Перед тем как добавить функцию или изменить поведение, проверь:

1. **Помогает ли это увидеть и прожить текущую неделю?** Если функция про далёкое будущее или про управление другими людьми — скорее всего, нет.
2. **Остаётся ли неделя на одном экране?** Новые элементы не должны вытеснять задачи или прятать их за кликами.
3. **Можно ли обойтись без нового поля?** Сначала ищи решение через текст, цвет или порядок, как у времени (`hh:mm`) и главной задачи.
4. **Работает ли это офлайн, на телефоне и в тёмной теме?** Если нет — задача не доделана.
5. **Не теряются ли данные?** Любое удаление должно иметь undo; массовые операции — копировать, а не перемещать, если на кону история.
6. **Не нарушает ли это бесплатность и приватность?** Никаких сторонних трекеров, рекламы и сбора данных сверх нужного для хранения задач.

Если ответ неочевиден — спроси владельца, а не додумывай. Если решение принято и оно меняет что-то из этого документа — обнови документ в том же изменении.
